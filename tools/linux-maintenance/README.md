# Linux maintenance primitives and recovery CI

This package extracts generic restart receipt, restart-counter attribution, and Linux process identity primitives for a future replacement of the historical private host-preparation helper. It contains no host names, operational paths, profile data, hash inventories, or deployment state. The deployed updater is not changed by this PR.

The receipt helper persists dispatch intent before a DBus call, persists the returned job path before observing it, and refuses replay after an ambiguous outcome. Only a valid systemd DBus job object path is accepted. An observer can resume read-only observation from a durable job receipt. Process checks require a stable MainPID, PID start-time identity, and the expected executable SHA256.

The counter classifier does not treat NRestarts as globally monotonic. A native transient-unit experiment records automatic retry, explicit RestartUnit, stop, and manual start values on the hosted Ubuntu systemd version. The same-run probe confirms whether explicit RestartUnit resets NRestarts. When it does, any nonzero count in the new invocation is treated as an automatic retry even when a job receipt exists. Unknown transitions fail closed.

The isolated GitHub job uses standard ubuntu-24.04 only. It downloads checksum-pinned official Xray 26.10.21 and 26.10.31 Linux archives, verifies their archive digests, and checks actual executable SHA/version. The native scenario starts baseline Xray, atomically replaces it with the candidate, verifies loopback HTTP through the SOCKS proxy, rejects a deliberately invalid candidate configuration, and recovers the baseline. Services run as the runner user inside an owned network namespace with loopback enabled and no default routes. Transient units and all files use unique stcvrc-ci-* names and RUNNER_TEMP-owned paths.

Missing systemd, sudo, namespace support, or required tools is reported as BLOCKED, never skipped. The experiment verifies this generic helper and hosted-runner behavior only; it does not claim that production updater code has changed or that production recovery is fixed. No Actions artifacts, cache, secrets, production units, routes, or VPN profiles are used.
