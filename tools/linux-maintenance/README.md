# Linux maintenance primitives and recovery CI

This package extracts generic restart receipt, restart-counter attribution, and Linux process identity primitives for a future replacement of the historical private host-preparation helper. It contains no host names, operational paths, profile data, hash inventories, or deployment state. The deployed updater is not changed by this PR.

The receipt helper persists dispatch intent before a DBus call, persists the returned job path before observing it, and refuses replay after an ambiguous outcome. An observer can resume read-only observation from a durable job receipt. Process checks require a stable MainPID, PID start-time identity, and the expected executable SHA256.

The counter classifier does not treat NRestarts as monotonic. A native transient-unit experiment records automatic retry, explicit RestartUnit, stop, and manual start values on the hosted Ubuntu systemd version. A counter decrease or unchanged count across a new invocation is accepted only with a matching durable job receipt. Unknown transitions fail closed.

The isolated GitHub job uses standard ubuntu-24.04 only. It downloads checksum-pinned official Xray 26.10.21 and 26.10.31 Linux archives, verifies their archive digests, and tests the actual executable SHA/version. The native scenario starts baseline Xray, atomically replaces it with the candidate, verifies loopback HTTP through the SOCKS proxy, rejects a deliberately invalid candidate configuration, and recovers the baseline. Services run only in an owned network namespace with loopback enabled and no default routes; transient units and all files are under RUNNER_TEMP and use unique stcvrc-ci-* names.

Missing systemd, sudo, namespace support, or required tools is reported as BLOCKED, never skipped. The experiment verifies this generic helper and hosted-runner behavior only; it does not claim that production updater code has changed or that production recovery is fixed. No Actions artifacts, cache, secrets, production units, routes, or VPN profiles are used.
